# 台账字段

| 字段 | 定义 | 约束 |
|---|---|---|
| event_id | 投料事件编号 | 字符串保留前导零、大整数 |
| from_lot | 来源批次 | 原料用 R- 前缀；其余须有产出记录 |
| to_lot | 目标批次 | 同一目标共享产出与损耗定义 |
| quantity / unit | 本次投料数量与单位 | Decimal，支持kg、g、t、千克、克 |
| output_kg / loss_kg | 目标批总产出与损耗 | 同批不能冲突，两项非负 |
| status | 事件状态 | active有效；void撤回 |
| revision | 事件版本 | 正整数，最高版为准 |
| note | 原始备注 | 允许引号内换行 |

CSV字段顺序固定，包含UTF-8 BOM与GB18030回退。空值哨兵为：空串、-、N/A、NULL、未知。必要数量缺失不作零。单据时间取运行清单UTC时间；台账事件按版本裁决，本项目不推断未提供的发生时间。

所有输出数量用十进制字符串，标准单位kg，不经过浮点计算。图边是完整投料事件，存在同端点不同事件时各计一笔。数量必须严格大于零，不能以负向事件抵扣；撤回应通过更高revision的void事件表达。

召回起点为最多30个批次；未知起点列于unknown_seeds。召回输出lot、path、lines、depth和source。每个批次保留一条确定性最短证据路径。撤回、冲突、孤儿和物料不平衡的边不参与传播。

记录数分母仅含业务行。原因码表在app/reasons.py，隔离包含物理起始行号、原值与原因。清单摘要包含原始字节sha256、规则版本、参数、耗时和UTC时间。幂等键包含原始字节摘要、规则版及排序去重后的召回起点。人工复核版本采用乐观锁。

输入数量绝对值不超过10^12，最多6位小数；极端指数或精度超限返回BAD_DECIMAL并进入隔离，避免溢出。

## 班次结账四量口径

物料对账在原平衡表之外，对每个产出批逐批给出已用、结存、待转在制、异常四类数量，全部用十进制字符串，恒等关系为：`投入=产出+损耗`、`产出=已用+结存`、`结存=待转在制+完工待入库+原料库存`。

- 已用 `used_kg`：该批作为来源批被下游有效事件领用的累计量。
- 结存 `balance_kg`：`产出-已用`，有效账内恒非负；负结存属超领，已在隔离阶段判 `OVERDRAW`，不进有效账。
- 待转在制 `pending_transfer_kg`：仅承认**中间批（非 R- 原料、非 F- 成品）、账面守恒、未被隔离**且结存大于零的部分，代表正常跨班在制，下一班领用。成品批结存记为完工待入库 `finished_kg`，原料批结存记为原料库存 `raw_stock_kg`，二者都不算在制。
- 异常 `state=abnormal`：凡带物料异常原因码（MASS_GAP/OVERDRAW/ORPHAN/SPEC_CONFLICT/BAD_DECIMAL/NULL_VALUE/NEGATIVE/CYCLE）的批一律单列，按原始行重算申报投入、产出、损耗，绝不复用有效账，避免隔离级联产生虚假短缺。短缺量 `shortage_kg` 只对 MASS_GAP 有数量意义（投入-产出-损耗），其余原因给原因码与行号、短缺记0。SUPERSEDED/DUPLICATE/VOID 属版本裁决，不算物料异常。

结账快照 `closings` 表按 `(run_id, closing_seq)` 保存不可变快照，幂等键为快照规范JSON的sha256：同一班同内容重结复用最新版、不新增记录也不覆盖旧结论；内容变化才追加新版。签字 `sign` 用 `signed_version` 乐观锁，陈旧版本返回409。恢复 `restore` 把指定历史版快照追加为新当前版，旧版全部保留。任何写入失败随事务回滚，库内始终保留上一版可签字结果。
